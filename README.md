# CalorieBot — Telegram-бот контроля питания

Бот следит за дневным лимитом — по калориям или по БЖУ напрямую (на выбор пользователя):
я задаю лимит, записываю съеденное и вижу, сколько ещё можно съесть в этом цикле — и что именно
из моих любимых продуктов ещё вписывается в остаток.

Управление **полностью кнопочное**: единственная команда — `/start` для инициализации,
дальше только ReplyKeyboard (меню) и InlineKeyboard (выбор продуктов, типов приёма пищи, подтверждения).

## Возможности

- **Дневной лимит — по калориям, по БЖУ напрямую или расчётом по формуле.** Помимо ручного ввода —
  калькулятор нормы: пол, возраст, рост, вес, уровень активности и цель (похудение/поддержание/набор),
  и бот сам считает базовый обмен (BMR, формула Миффлина — Сан-Жеора), суточную норму с поправкой на
  активность (TDEE) и раскладывает целевую калорийность на БЖУ в граммах — с подтверждением перед
  применением. Прогресс и подбор избранного считаются под выбранный режим.
- **Прогресс + история одним экраном.** «📊 Мой прогресс» показывает остаток (ккал либо Б/Ж/У —
  смотря что отслеживается), полоски прогресса и сразу историю текущего цикла по приёмам пищи.
  Перебор подсвечивается ⚠️.
- **Запись приёмов пищи** — из избранного в один-два тапа или новым продуктом (название → БЖУ на 100 г
  или сразу на порцию → при вводе на 100 г бот попросит вес порции и сам пересчитает КБЖУ на неё).
- **Избранные продукты — фиксированная порция или на 100 г.** Фиксированная (например, батончик) —
  логируется одним тапом как есть. На 100 г (например, рис) — при добавлении в дневник бот каждый раз
  спрашивает съеденный вес и пересчитывает КБЖУ. Оба параметра — КБЖУ и тип порции — можно
  редактировать позже, без пересоздания продукта.
- **Ручной сброс — 🆕 Новый день.** Автосброса по календарным суткам нет: у людей разные жизненные ритмы,
  поэтому счётчик обнуляется только тогда, когда пользователь сам это скажет (с подтверждением, чтобы
  случайный тап ничего не стёр). Закрытый цикл сохраняется в историю.
- **История прошлых циклов — редактируемая.** 📅 История: список закрытых циклов (по 7 штук на странице)
  со сводкой по каждому. Тап по циклу открывает карточку, где можно задним числом удалить отдельную
  запись или добавить новую — сохранённый снимок цикла (калории/БЖУ/счётчик) пересчитывается автоматически.
- **Отчёт за неделю/месяц.** В «📊 Мой прогресс» — кнопки «За неделю»/«За месяц»: среднее потребление,
  сколько дней был перебор/недобор, и текстовая рекомендация по последнему завершённому дню
  (например, «вчера не хватило белка на 20 г → ближайшие 1-2 дня ориентир выше» — сам лимит при этом
  не меняется, только подсказка).
- **Предупреждение о повторе.** Если в текущем цикле уже есть запись с таким же названием, перед
  сохранением бот спросит — заменить прежнюю запись или добавить рядом как отдельный приём пищи.
- **Избранное — по группам, а не одним огромным списком.** «⭐ Избранное» делится на три раздела:
  - **💧 Вода** — жидкости (в том числе калорийные — морс, сок), КБЖУ хранится на 1 литр, объём
    спрашивается при каждом добавлении в дневник, как обычная плавающая порция;
  - **🍱 Готовые блюда** — КБЖУ считается автосуммой ингредиентов, а не вводится вручную: блюдо
    создаётся пустым, потом наполняется ингредиентами по одному — из избранных продуктов или
    произвольным (не избранным) — добавить/убрать можно в любой момент;
  - **🥘 Продукты** — обычные продукты с пользовательскими подкатегориями (изначально четыре: «Белковые
    продукты», «Зерновые и крахмалистые», «Овощи и фрукты», «Жиры» — их, как и любые новые, можно
    переименовывать и удалять). Продукт можно «перетащить» в другую подкатегорию карточкой.

## Стек

- .NET 8.0, ASP.NET Core (минимальный хост: health check + фоновая служба поллинга)
- [Telegram.Bot](https://github.com/TelegramBots/Telegram.Bot) 22.0
- PostgreSQL 16 + Entity Framework Core 8 (Npgsql), миграции
- Docker + docker-compose

## Схема базы данных

**Users**

| Колонка | Тип | Примечание |
|---|---|---|
| UserId | bigint PK | id из Telegram |
| Username / FirstName | text | обновляются при каждом обращении |
| TrackingMode | int NOT NULL DEFAULT 0 | 0 — по калориям, 1 — по БЖУ напрямую |
| DailyCalorieLimit | int NOT NULL DEFAULT 2000 | дневной максимум; в режиме БЖУ — расчётная величина |
| DailyProteinsLimit / DailyFatsLimit / DailyCarbsLimit | numeric(7,2) | в режиме «калории» — ориентиры 30/30/40 %, в режиме «БЖУ» — заданные напрямую лимиты |
| CreatedAt | timestamptz DEFAULT now() | |
| GoalSetAt | timestamptz NULL | когда лимит меняли явно |
| CycleStartedAt | timestamptz NOT NULL DEFAULT now() | начало текущего цикла КБЖУ; двигается кнопкой «🆕 Новый день» |

**FavoriteProducts**

| Колонка | Тип | Примечание |
|---|---|---|
| Id | serial PK | |
| UserId | bigint FK → Users | ON DELETE CASCADE |
| Name | text NOT NULL | уникален в паре с UserId |
| Calories | int NOT NULL | считается из БЖУ; для нефиксированной порции — на 100 г |
| Proteins / Fats / Carbs | numeric(7,2) DEFAULT 0 | для нефиксированной порции — на 100 г |
| IsFixedServing | bool NOT NULL DEFAULT true | true — КБЖУ на одну порцию (батончик), false — КБЖУ на 100 г/1 л, вес или объём спрашивается при логировании |
| ServingSize | text NULL | «200 г», «1 стакан» — только для фиксированной порции |
| CreatedAt | timestamptz DEFAULT now() | |
| CategoryKind | int NOT NULL DEFAULT 0 | 0 — Продукт, 1 — Вода, 2 — Готовое блюдо |
| ProductCategoryId | int NULL FK → ProductCategories | ON DELETE SET NULL; только для CategoryKind = Продукт |

**ProductCategories** — пользовательские подкатегории группы «Продукты»

| Колонка | Тип | Примечание |
|---|---|---|
| Id | serial PK | |
| UserId | bigint FK → Users | ON DELETE CASCADE; уникальна в паре с Name |
| Name | text NOT NULL | |
| IsBuiltIn | bool NOT NULL DEFAULT false | одна из 4 заведённых автоматически — прав не даёт и не отнимает, можно переименовать/удалить как любую |

**DishIngredients** — состав готового блюда (снимок КБЖУ на момент добавления)

| Колонка | Тип | Примечание |
|---|---|---|
| Id | serial PK | |
| DishFavoriteProductId | int FK → FavoriteProducts | ON DELETE CASCADE; ссылается на продукт с CategoryKind = Готовое блюдо |
| Name, Proteins, Fats, Carbs, Calories | | КБЖУ ингредиента; сумма всех ингредиентов блюда пересчитывается в FavoriteProducts при каждом добавлении/удалении |

**FoodLog**

| Колонка | Тип | Примечание |
|---|---|---|
| Id | serial PK | |
| UserId | bigint FK → Users | ON DELETE CASCADE |
| ProductName, Calories, Proteins, Fats, Carbs, ServingSize | | копия КБЖУ на момент записи |
| MealType | int | 1 завтрак, 2 обед, 3 ужин, 4 перекус |
| LoggedAt | timestamptz DEFAULT now() | UTC; принадлежность циклу считается по `Users.CycleStartedAt` |
| IsFavorite | bool DEFAULT false | продукт связан с избранным |
| FavoriteProductId | int NULL FK | ON DELETE SET NULL — история не теряется |

**CalorieCycles** — снимок каждого закрытого цикла (кнопка «🆕 Новый день»)

| Колонка | Тип | Примечание |
|---|---|---|
| Id | serial PK | |
| UserId | bigint FK → Users | ON DELETE CASCADE |
| StartedAt / EndedAt | timestamptz | границы цикла |
| CalorieLimit | int NOT NULL | лимит, действовавший в цикле (на момент закрытия) |
| ConsumedCalories, Proteins, Fats, Carbs | | итоги цикла — пересчитываются при редактировании записей задним числом через «📅 История» |

Индексы: `FoodLog (UserId, LoggedAt)` под запрос «что съедено в этом цикле»,
`FavoriteProducts (UserId, Name)` UNIQUE против дублей, `CalorieCycles (UserId, EndedAt)` под историю циклов,
`ProductCategories (UserId, Name)` UNIQUE против дублей подкатегорий.

## Развёртывание на сервере (VPS) — одна команда

Ничего в файлах руками редактировать не нужно — только вставить токен, когда скрипт попросит.

```bash
git clone https://github.com/bugattiloh/CalorieBot.git
cd CalorieBot
./deploy.sh
```

Скрипт сам, по порядку:

1. проверяет, установлен ли Docker — если нет, спрашивает подтверждение в консоли
   (`[Y/n]`) и ставит его официальным скриптом `get.docker.com`;
2. при первом запуске создаёт `.env` из `.env.example`, спрашивает в терминале **только**
   `BOT_TOKEN` (из @BotFather: `/mybots` → бот → *API Token*) и сам генерирует случайный
   пароль для PostgreSQL — вводить его не нужно;
3. собирает образ, поднимает `postgres` и `bot` через `docker compose`;
4. дожидается, пока оба сервиса станут healthy (до 2 минут), и выводит команду для проверки.

При повторных запусках (например, после `git pull` с обновлениями) скрипт увидит уже
заполненный `.env` и ничего не спросит — просто пересоберёт и перезапустит контейнеры.

Что происходит под капотом при каждом старте бота:

1. поднимается `postgres` с именованным томом `caloriebot-postgres-data`;
2. бот дожидается healthcheck базы (`pg_isready`), накатывает EF-миграции и начинает поллинг;
3. на `http://localhost:8080/health` появляется статус сервиса.

### Вручную, шаг за шагом

Если нужен больший контроль, то же самое можно сделать руками:

```bash
cp .env.example .env      # затем заполнить BOT_TOKEN и POSTGRES_PASSWORD
docker compose up -d --build
```

### Проверить

```bash
docker compose ps                 # состояние и health обоих сервисов
docker compose logs -f bot        # логи в JSON
curl http://localhost:8080/health # postgres + telegram
curl http://localhost:8080/       # имя бота, счётчик обработанных апдейтов
```

В Telegram: открыть бота и отправить `/start`.

### Обновление и остановка

```bash
docker compose up -d --build      # пересобрать после изменений кода
docker compose stop               # остановить (graceful, до 30 секунд)
docker compose down               # остановить и удалить контейнеры (том с данными остаётся)
docker compose down -v            # удалить и данные тоже
```

## Локальный запуск без Docker

```bash
# 1. База (например, в контейнере)
docker compose up -d postgres

# 2. Токен и строка подключения
export Bot__Token="<токен>"
export ConnectionStrings__Default="Host=localhost;Port=5432;Database=caloriebot;Username=caloriebot;Password=<пароль>"

# 3. Запуск
dotnet run --no-launch-profile --project src/CalorieBot.Api
```

`--no-launch-profile` обязателен: профиль в `Properties/launchSettings.json` держит `Bot__Token`
пустым для безопасности и без этого флага перезатирает переданный вами токен.

## Тесты

Юнит-тесты лежат в `tests/CalorieBot.Tests` (xUnit + Moq + EF Core InMemory) и покрывают
основные сценарии бота: расчёт калорий и валидацию ввода (включая строгий формат БЖУ — не больше
одного знака после запятой, без отрицательных значений), сервисы (`UserService`,
`FavoriteProductService`, `FoodLogService`, `ProgressService`, `CycleService`) и сами сценарии диалогов
(`MealScenario`, `FavoritesScenario`, `DishScenario`, `LimitScenario`, `ProgressScenario`, `CycleScenario`) —
Telegram-клиент в них подменён записывающей заглушкой, поэтому реальная сеть не нужна.

```bash
dotnet test
```

## Миграции EF Core

Миграции применяются автоматически при старте (`DatabaseMigratorHostedService`, до 10 попыток с паузами —
на случай, когда база ещё поднимается). Вручную:

```bash
# создать новую миграцию
dotnet ef migrations add <Name> --project src/CalorieBot.Data --startup-project src/CalorieBot.Api

# применить к работающей базе
export ConnectionStrings__Default="Host=localhost;Port=5432;Database=caloriebot;Username=caloriebot;Password=<пароль>"
dotnet ef database update --project src/CalorieBot.Data --startup-project src/CalorieBot.Api
```

## Как это работает внутри

- **Один scope на апдейт.** `BotUpdateHandler` создаёт scope, внутри живут `DbContext` и сервисы;
  любое исключение логируется и превращается в вежливое сообщение пользователю — поллинг не падает.
- **Состояния диалогов** (`ConversationState`) лежат в `IMemoryCache` со скользящим часом:
  брошенные на середине диалоги вычищаются сами.
- **Кэш** на профиль пользователя и список избранного (10 минут, сбрасывается при любой записи) —
  на каждое нажатие кнопки в базу я не хожу.
- **Калории** считаются один раз в `CalorieCalculator`: `Б×4 + Ж×9 + У×4`.
- **Цикл КБЖУ не привязан к календарю.** Границы текущего цикла — `[Users.CycleStartedAt; сейчас)`,
  автосброса по расписанию нет: у людей разные жизненные ритмы, поэтому только сам пользователь решает,
  когда нажать «🆕 Новый день». `DayClock` при этом остаётся: фиксированное смещение UTC+3
  (без зависимости от tzdata в контейнере) нужно для отображения времени, а не для сброса счётчика.
- **Валидация** всего текстового ввода — в `InputParser`: название 2–64 символа, БЖУ — ровно три числа
  (точка или запятая, до 1000 г), лимит — 500–10000 ккал.
- **Логи** — JSON в stdout, со скоупами `UpdateId` / `UpdateType` / `UserId`.
- **Health check** — `/health`: доступность PostgreSQL (`AddDbContextCheck`) и состояние поллинга.
- **Graceful shutdown** — `ReceiveAsync` завершается по `CancellationToken`, у хоста 15 секунд
  на дозавершение, у контейнера — 30.

## Сценарии

1. **Прогресс + история.** 📊 Мой прогресс → остаток (ккал либо Б/Ж/У — смотря что отслеживается),
   подходящие любимые продукты, история текущего цикла — всё одним сообщением.
2. **Еда из избранного, фиксированная порция.** 🍽 → 💝 Из любимых → продукт → тип приёма пищи →
   запись и обновлённый прогресс.
3. **Еда из избранного, плавающая порция.** 🍽 → 💝 Из любимых → продукт (например, рис) →
   бот спрашивает съеденный вес → пересчитывает КБЖУ → тип приёма пищи → запись.
4. **Новый продукт.** 🍽 → 🔍 Новый продукт → название → «на 100 г» или «на порцию целиком» → БЖУ →
   (если «на 100 г» — ещё вес порции, бот пересчитывает КБЖУ на него) → «Сохранить в избранное?» →
   тип приёма пищи → запись.
5. **Смена лимита по калориям.** 🎯 Дневной лимит → ✏️ Изменить лимит → 📐 По калориям → число → готово.
6. **Смена лимита по БЖУ.** 🎯 Дневной лимит → ✏️ Изменить лимит → 🥩 По БЖУ → три числа (Б Ж У) →
   калории и % от лимита в подборе избранного пересчитываются от них.
6a. **Расчёт нормы КБЖУ по формуле.** 🎯 Дневной лимит → ✏️ Изменить лимит → 🧮 Рассчитать по формуле →
   пол → возраст → рост → вес → уровень активности → цель (похудение −15% / поддержание / набор +15% от
   нормы) → карточка с базовым обменом (BMR), суточной нормой (TDEE), целевой калорийностью и БЖУ в
   граммах → «✅ Применить» сохраняет результат как лимит по БЖУ (или «❌ Отмена» ничего не меняет).
   Белки считаются от веса тела (2 г/кг при похудении, 1.8 при наборе, 1.6 при поддержании), жиры —
   1 г/кг всегда, углеводы — остаток целевой калорийности.
7. **Редактирование избранного.** ⭐ → 🥘 Продукты → подкатегория → тап по продукту → карточка с
   действиями: ✏️ изменить КБЖУ (переиспользует шаги добавления, обновляет запись по имени),
   🔁 сменить тип порции без изменения КБЖУ, 📂 перенести в другую подкатегорию, 🗑 удалить.
8. **Новый день.** 🆕 Новый день → подтверждение (текущий цикл: с какого момента, сколько съедено) →
   да → цикл сохраняется в историю, счётчик обнуляется, начинается новый цикл.
9. **История циклов — просмотр и редактирование.** 📅 История → список закрытых циклов по 7 штук на
   странице → тап по циклу → карточка (записи — кнопками): тап по записи удаляет её (с подтверждением),
   «➕ Добавить запись» — задним числом заносит приём пищи в этот цикл. Сохранённый снимок цикла
   пересчитывается после любого изменения.
10. **Отчёт за период.** 📊 Мой прогресс → «📈 За неделю» / «📈 За месяц» → сводка по завершённым дням
    (сегодняшний, ещё не закончившийся день в неё не входит) плюс текстовая рекомендация по последнему
    дню — сам лимит при этом не меняется.
11. **Предупреждение о повторе.** 🍽 → любой способ добавления → тип приёма пищи → если продукт с
    таким же названием уже есть в этом цикле, бот спрашивает: заменить прежнюю запись или добавить
    рядом как новую.
12. **Вода.** ⭐ → 💧 Вода → продукт (или «➕ Добавить жидкость» — название и БЖУ на 1 литр без лишних
    шагов) → при логировании бот спрашивает объём в литрах и пересчитывает КБЖУ линейно.
13. **Готовые блюда.** ⭐ → 🍱 Готовые блюда → «➕ Создать блюдо» → название → карточка блюда (КБЖУ 0) →
    «➕ Добавить ингредиент» → источник ингредиента: ⭐ из избранного (продукт из «Продуктов»; фиксированная
    порция добавляется как есть, плавающая — сначала спрашивается вес) или 🔍 свой (название + БЖУ вручную,
    в избранном не сохраняется) — сколько угодно раз, КБЖУ блюда каждый раз пересчитывается автосуммой.
    Блюдо логируется в дневник как обычный фиксированный продукт.
14. **Подкатегории «Продуктов».** ⭐ → 🥘 Продукты → «➕ Новая категория» (название) или «✏️ Управлять» →
    тап по подкатегории → ✏️ переименовать / 🗑 удалить (продукты внутри не удаляются, становятся
    «без подкатегории»).

## Пересчёт БЖУ на порцию

Везде, где вводится БЖУ (новый продукт в дневник, новое избранное), бот сначала спрашивает,
как удобнее его ввести:

- **На порцию целиком** — введённые числа записываются как есть.
- **На 100 г продукта** — бот дополнительно спрашивает вес порции в граммах и масштабирует
  БЖУ линейно (`значение_на_100г × вес / 100`), после чего считает калории по обычной формуле
  Б×4 + Ж×9 + У×4. Размер порции автоматически проставляется как введённый вес (например, «150 г»).
